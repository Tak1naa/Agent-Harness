# 参考文献与阅读顺序

核查日期：2026-10-22。以下使用作者论文、作者机构、正式会议页面或官方仓库核对题名与作用。未核实的页码不补写；预印本明确标注。配套 `references.bib` 可导入文献管理软件。文献支持研究设计，不构成本项目实验结果。

## 最优先阅读的四篇

1. **PIZZORNO J A, BERGER E D. CoverUp: Effective High Coverage Test Generation for Python[J]. Proceedings of the ACM on Software Engineering, 2025. DOI: 10.1145/3729398.** [作者全文](https://arxiv.org/html/2403.16218v4)

   方法上最接近：组合代码上下文、覆盖率和执行反馈生成Python测试。重点读第3节方法、第4.6节消融和第5节有效性威胁。本项目应将“覆盖代码”与“实际违反安全性质”区分，不能仅更换工具名称就宣称方法创新。早期预印本题名为 Coverage-Guided LLM-Based Test Generation；这里采用2025年版本题名。

2. **MATHEWS N S, NAGAPPAN M. Design choices made by LLM-based test generators prevent them from finding bugs[EB/OL]. arXiv:2412.14137, 2024.** [作者全文](https://arxiv.org/html/2412.14137v1)

   支撑判据设计：只保留在当前实现上通过的测试，可能把已有缺陷固化为正确行为。重点读方法、讨论及有效性威胁。本项目使用预先定义的安全性质，并保留真实安全失败；不能把修订目标写成“让所有测试在缺陷版通过”。该论文研究范围与本项目三类安全漏洞不同，不能直接套用其效果数字。

3. **SIDDIQ M L, SANTOS J C S. SecurityEval Dataset: Mining Vulnerability Examples to Evaluate Machine Learning-Based Code Generation Techniques[C]//MSR4P&S. 2022. DOI: 10.1145/3549035.3561184.** [作者原文](https://lsiddiqsunny.github.io/public/securityeval.pdf)；[作者数据仓库](https://github.com/s2e-lab/SecurityEval)

   支撑代码生成安全评估和CWE分类。原论文介绍130条样本、75种弱点；仓库结构含生成提示和不安全代码示例，也使用Bandit/CodeQL评估。它不等于可以直接运行的缺陷／修复配对安全测试集。后续引入要固定版本、审核来源与许可证，并补充可执行入口、功能检查和动态判据；目前未计入本项目30对样本。

4. **KONSTANTINOU M, DEGIOVANNI R, PAPADAKIS M. How well LLM-based test generation techniques perform with newer LLM versions?[EB/OL]. arXiv:2601.09695v2, 2026.** [作者预印本](https://arxiv.org/abs/2601.09695v2)

   支撑强基线与模型版本控制。该研究发现，新模型下简单直接生成可能胜过部分复杂框架；这不预告本项目结果，但说明A组必须认真实现，不能故意削弱提示。当前仅作为2026年预印本引用，不写成已核实的顶会录用论文。

## 补充基础与方法

5. **BARR E T, HARMAN M, MCMINN P, et al. The Oracle Problem in Software Testing: A Survey[J]. IEEE Transactions on Software Engineering, 2015, 41(5): 507–525. DOI: 10.1109/TSE.2014.2372785.** [作者机构资料](https://discovery.ucl.ac.uk/id/eprint/1471263/)

   支撑“给定输入后如何判断行为正确”的测试判据问题。用于解释为什么普通异常、Mock命中和高覆盖率不等于漏洞证据，以及为什么安全与功能正确性要分别评价。

6. **LEMIEUX C, INALA J P, LAHIRI S, et al. CODAMOSA: Escaping Coverage Plateaus in Test Generation with Pre-trained Large Language Models[C]//ICSE. 2023.** [作者机构论文页](https://www.microsoft.com/en-us/research/publication/codamosa-escaping-coverage-plateaus-in-test-generation-with-pre-trained-large-language-models/)

   将搜索式测试与LLM结合，在覆盖增长停滞时请求新测试种子。可借鉴“何时调用模型”的调度思路；它主要优化覆盖，不是本项目漏洞复现率的现成对照结果。

7. **KANG S, YOON J, YOO S. Large Language Models are Few-shot Testers: Exploring LLM-based General Bug Reproduction[C]//ICSE. 2023.** [作者论文](https://arxiv.org/abs/2209.11515v3)

   LIBRO以缺陷报告为输入生成复现测试，并通过后处理排序测试。适合后续真实缺陷的buggy/fixed配对评估；当前任务输入、语言和安全性质与其不同，不能把论文中的复现率当作可直接比较的基线。

8. **PEARCE H, AHMAD B, TAN B, et al. Asleep at the Keyboard? Assessing the Security of GitHub Copilot's Code Contributions[C]//IEEE Symposium on Security and Privacy. 2022.** [作者论文](https://arxiv.org/abs/2108.09293v3)

   用于研究背景：生成代码可能存在安全问题。开题中“约40%”必须限定为这篇历史研究所构造场景和当时版本的实验结果；不能说当前所有大模型生成代码都有40%的漏洞或逻辑错误。

## 工程资料单列

9. **PyCQA. Bandit documentation[EB/OL].** [官方文档](https://bandit.readthedocs.io/en/latest/)（访问：2026-10-22）。说明其通过AST插件查找常见Python安全问题。本项目实际版本1.8.6，静态告警与动态证据分开统计。

10. **DeepSeek-AI. DeepSeek Harness[EB/OL].** [官方仓库](https://github.com/deepseek-ai/deepseek-harness)（访问：2026-10-22）。本项目固定SDK 0.2.1rc2及上游commit `687f282e8625c6b8d11ff58211a90524be2e4317`。它提供编排能力；本项目已验证SDK初始化和MCP协议，正式对照使用直接API，尚未验证带模型的完整Harness工具调用回合。

答辩正文优先引用1、2、3，问答与报告补充4—8。工具官网用于说明复用关系，不能替代研究论文。五分钟正文仍保持7页；完整文献放报告和答辩备份资料，避免占用现场讲述时间。

## 对开题表述的修正

- 将“首次提出”“尚未形成相关方法”改为本项目具体研究问题，已有CoverUp、CodaMosa、LIBRO等工作，未经系统检索不能声称首创。
- 将“缺陷检出率提高30%以上”作为原计划设想的历史记录；当前报告不预设提升比例。
- 当前AST模块做局部函数和敏感调用整理，没有实现完整CFG、污点分析或符号执行证明。
- 当前LLM选择输入和受限测试策略，临时资源及安全断言由可信探针提供；尚未实现通用项目Harness或自动Stub/Mock构造。
