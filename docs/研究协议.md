# 冻结实验协议 v0.1

研究假设：在同一模型、统一受限测试语法和最多3次生成调用下，风险上下文能提高缺陷复现率。允许零提升或负提升。2026-10-22 已开展真实模型开发集试验；冻结评测尚未开展。开发期可修改提示和执行反馈，每轮单独冻结源码哈希与镜像 ID，不合并不同轮次作为正式对照结果。

## 数据与信息边界

受控集30对（6开发、24评测），每类10对；各类01—02仅开发。所有数据均为人工构造模板变体，记录出处、修改及哈希。冻结后不得根据实验结果更改评测集。另以12项正常功能任务生成模型代码，每类4项，全量保留；两名成员交叉核验，分歧标unknown并单列。受控集与生成集不能混算。

A获得需求、代码、统一probe规范；B增加Bandit告警；C增加AST提取的风险函数、签名、导入和敏感调用。三组都看到同一份完整单文件源码，C测试的是显式定位和整理上下文的增益。固定版、人工标签、参考触发输入不进入提示。人工参考测试与主模型隔离。

## 模型与预算

每样本×每组独立重复3次，温度0，最大输出1800Token。最多生成1次、按缺陷版执行反馈修订2次，只改测试。成功可早停，同时报告实际调用与Token消耗；相同的是预算上限，不强行让成功组耗尽预算。对照组在每个样本/重复块内随机排序，块顺序固定种子20261020。正式controlled共216个trial，最多648次API请求；generated共108个trial，最多324次，另12次代码生成。

首次开发集×1重复的18个trial测成本。总规划预算100元，所有入口共用账本，保守预留余额不足即停止。正式模型、实时价格、镜像ID、prompt源码哈希、数据哈希随运行冻结。实验记录实际返回的模型标识，不能只写“DeepSeek”。当前SDK检查和测试替身都不算真实模型调用。

## 动态判据与失败分类

路径穿越：独立临时目录外的随机哨兵内容被返回。命令注入：攻击输入在容器内真正创建无害标记文件。SQL注入：内存SQLite查询返回标记为PRIVATE的行。统一probe管理入口和资源，模型仅选择输入、组合受限Hypothesis策略。限制生成语法是可验收范围收敛。

缺陷版violation且修复版pass才构成受控集确认复现。固定版反馈不传回模型。普通异常、语法错误、导入失败、虚假的assert、超时分别计入失败，不能视为漏洞。参考测试仅工程验收。rootless、无网络、非特权、无capability、只读根、资源限制未满足时停止执行。容器是进程隔离层，不声称抵御未知内核漏洞或目标刻意篡改同进程测试oracle；后者是后续信任边界改进。

## 指标与分母

- 可运行率：受控集须两版都正常完成安全判定，成功trial/所有已完成trial。所有生成失败保留。
- 缺陷复现率：受控集确认配对数/所有受控trial；生成集确认触发数/人工确认有漏洞trial。
- 安全版误报率：修复版violation数/所有受控trial；生成集触发数/人工确认安全trial。执行失败另列，不能解释为安全。另报告 `negative_valid_evaluations`（有效安全判定数）、`negative_unresolved`（失败或未运行数）及 `observed_false_positive_rate`（仅有效判定为分母）；两种分母不得混用。
- 覆盖率：只测目标代码分支，不含测试代码；零分支程序排除分支均值分母，并报告该分母。主表采用最终测试在缺陷版的覆盖率。
- 耗时：全部生成尝试的执行时间加最后修复版执行时间；模型响应耗时另列（若未采集则缺失），不能将执行时间称作端到端总耗时。
- Token：全部尝试API报告输入/输出用量。缺失用量不能默认为实际0，用保守预算账本辅助核查。

summary.csv可由原始JSON重新生成。组间比较只用完整A/B/C匹配块；小样本先报告逐样本胜负与失败分布，不把重复运行当成独立新样本。将来做区间估计时应按样本聚类bootstrap；当前不提供显著性或“提升30%”结论。

## 当前证据和局限

参考测试30/30配对成立，修复版0/30触发；开发6/6、评测24/24分别记录。评测仅5例有分支，平均分支覆盖0.5，其余19例零分支，不能宣称100%分支覆盖。小而相似的手工样本对生产代码代表性有限。AST是局部语法整理，没有跨文件调用图或污点证明。正常功能测试不足，拒绝全部输入的程序可能满足这些安全性质，因此必须将功能正确性与安全性分别评价。
